# Codex 窗口状态

本机 Windows 小工具：通过 Codex 插件已有的状态通信，将已发现会话集中显示在精简网页里。
无需安装 npm 依赖，不调用模型，也不修改 Codex 配置。

## 使用

1. 双击“启动监控.cmd”。工具在后台运行，默认浏览器打开面板。
2. 关闭最后一个监控标签页后，约 10 秒自动停止监控；刷新或在这期间重新打开可继续使用。还有其他监控标签页时继续运行，切到后台或其他桌面也不会主动停止。
3. 双击“停止监控.cmd”停止该工具。它不会停止或干预 Codex 的任务。

启动后若 60 秒内没有监控页面建立连接，工具也会自动退出。
自动退出后需要再次双击“启动监控.cmd”；尚在运行时重复启动会打开同一实例。
退出计时以浏览器与服务的事件流断开为准；电脑睡眠、浏览器冻结等情况可能延迟识别。

运行需要 Windows 上已有的 Node.js 22 或更高版本；本机已使用 Node.js 24 验证。
如果运行入口报错，可在此文件夹的 PowerShell 中执行：

    node src/service.cjs --open

停止：

    node src/service.cjs --stop

本机访问链接记录在 .runtime/instance.json；该文件包含随机访问凭据，请勿公开分享。
每次停止后重新启动可使用不同端口和凭据，应使用启动入口打开。

## 页面

- 默认按已发现窗口汇总，可按状态筛选、搜索窗口及会话的项目名称/路径、优先显示空闲窗口。同一客户端的多个 Codex 会话只占一行，详情保留各会话状态。
- 主列表的项目名称与执行状态分别汇总：名称优先采用唯一经过 IDE 目录核对的项目；无法从多个项目中唯一确认时显示“多项目窗口”，各会话的原始目录保留在详情中。
- 手动阻塞：点击“标记阻塞”，可填写最多 500 字的原因；该窗口始终排在普通窗口之后，实际 Codex 状态和状态筛选保持不变。可编辑原因，点击“解除阻塞”恢复正常排序。
- 阻塞标记仅保存在本次监控服务的内存中，多标签页同步，刷新页面仍保留；服务退出或窗口离线移除后清除，不写入文件。
- 空闲：当前轮结束，或有明确的等待用户输入标记。
- 执行中：Codex 正在处理当前轮，包括思考和调用工具。
- 待回答：当前交互中存在尚未收到已接受回复的结构化问题。按协议的有序历史索引和根轮次识别当前交互，新任务替换旧交互；自动续行和仅包含结构化问题回复的后续轮次延续原交互，历史旧问题不累加到当前计数。空闲时显示“等待回答”，仍在执行时显示“执行中 · 待回答”，统一使用琥珀色标签；回答或跳过并被接受后清除对应标记。
- 有待回答问题的窗口优先排列，手动阻塞仍始终置底；状态筛选和时长继续按真实执行状态计算。问题记录不完整或未确认时会明确提示，断线后取消旧的待回答排序。
- 待处理：明确等待审批或确认。
- 窗口中任一会话执行时显示执行中；没有执行中但有待处理时显示待处理；有状态未确认时不计为空闲，全部会话空闲才显示空闲。
- 未知：没有有效快照、断线、协议不兼容或正在重新同步。未知不会被计为空闲。
- 初次接入只能确认“至少已持续多久”；已观察到变化后，显示真实监测到的状态时长。
- 列表时长按分钟显示，未满一分钟显示“不到 1 分钟”；详情打开时按秒实时更新，超过一小时仍显示秒数。
- 详情显示项目路径、状态原因、窗口对应情况、最后确认时间及短标识。
- 每行“前往窗口”可激活现有 VS Code 窗口，并切到它所在的虚拟桌面；最小化窗口会恢复。
- 先按窗口标题中的项目名称匹配。存在多个候选或未能自动定位时，选择框会显示窗口标题、桌面及最小化状态，选择后本次监控运行期间会记住对应关系。
- 窗口关闭重开、项目变化或监控重启后可能需要重新选择。自定义/未匹配标题发生变化时也会重新确认，避免使用过期对应关系。

## 覆盖与限制

当前已核对本机 openai.chatgpt 26.1106.51428 的内部通信协议（状态流版本 11）。升级插件后若协议改变，
工具会显示未知或等待连接，需要重新核对适配。

采集通信断开时，旧条目会暂时保留并显示未知；重连成功后等待约 10 秒重新发现会话，未被重新发现的旧条目会自动移除。已重新发现但尚未取得状态的会话仍显示未知。

长会话的常规状态快照可能包含较大的历史数据；单条 IPC 消息接收上限为 256 MiB，超出上限仍会拒收并重连。大快照解码会临时增加内存占用；解码后仅保留受限的状态元数据，不保存聊天正文或工具输出。

列表代表已发现的 Codex 窗口，当前以面板客户端识别归属，不枚举未打开 Codex 的普通 VS Code 窗口。
同一个客户端的多个会话会汇总，详情中分别显示；不同客户端即使目录相同也保留独立行，窗口归属不能唯一确定时明确提示。一个会话的多个跟随视图
不会主动被当成多个执行任务。隐藏/从未加载的面板可能无法发现。

等待输入/审批按明确的运行状态标记识别；异步问题另从常规快照和增量携带的 canonical history 中识别，仅保留问题和轮次关联 ID、数量和同步状态。无关历史条目仅保留增量定位所需的索引占位，不解析其推理、工具输入或输出。不会持续请求完整历史；未加载的历史、无法确认最新交互、超出解析上限或不支持的结构会标为未完全同步/未确认。协议测试覆盖不等于全部真实窗口场景均已实测。
工具不通过 CPU 占用、无输出时间或聊天内容猜测状态。

“前往窗口”的自动对应依据窗口标题中的项目名称，不保证完整目录身份；同名/同目录多个条目需要手动选择。
Windows 若拒绝前台激活，页面会提示失败，可再点一次或按 Win+Tab 切换。
此功能使用 Windows 自带 PowerShell 与公开原生接口；仅点击时启动短时助手，不新增常驻进程。

## 本机与数据

仅监听 127.0.0.1，随机凭据保护页面和本地接口，浏览器通过事件流实时更新。
只保留最小状态元数据，不保存聊天正文、推理或工具输出。退出时不触及 Codex 工作进程。
没有系统服务、开机启动、桌面通知或远程访问。

## 开发

项目仅使用 Node.js 内置模块，运行无需 npm install。

现有自动检查：

    node --test

| 目录或文件 | 职责 |
| --- | --- |
| src/protocol.cjs、src/collector.cjs | IPC 消息帧、只读白名单、状态发现、订阅与重连 |
| src/state.cjs | 会话状态、修订校验与窗口汇总 |
| src/input-state.cjs | 结构化问题与已接受回复的最小元数据投影 |
| src/web.cjs、src/service.cjs | 本机 HTTP/SSE、鉴权、单实例与服务生命周期 |
| src/windows.cjs、src/native/ | 窗口匹配及短时 PowerShell/C# 原生助手 |
| public/ | 面板、筛选、计时与窗口选择 |
| test/ | 现有协议、采集、网页、浏览器脚本及生命周期测试 |
| Start.ps1、Stop.ps1 | 启动和停止入口 |

开发约束见 [AGENTS.md](AGENTS.md)。自动协议测试不能替代真实 Windows 窗口、浏览器睡眠和长期运行场景的验证。
报告问题时，请提供 Windows、Node.js 和 Codex 插件版本，并对路径、项目名称、窗口标题及会话标识脱敏。

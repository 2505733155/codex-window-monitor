# Codex 窗口状态

本机 Windows 小工具：通过 Codex 插件已有的状态通信，将已发现会话集中显示在精简网页里。
无需安装 npm 依赖，不调用模型，也不修改 Codex 配置。

## 使用

1. 双击“启动监控.cmd”。工具在后台运行，默认浏览器打开面板。
2. 关闭最后一个监控标签页后，约 10 秒自动停止监控；刷新或在这期间重新打开可继续使用。还有其他监控标签页时继续运行，切到后台或其他桌面也不会主动停止。
3. 双击“停止监控.cmd”停止该工具。它不会停止或干预 Codex 的任务。

启动后若 60 秒内没有监控页面建立连接，工具也会自动退出。
自动退出后需要再次双击“启动监控.cmd”；尚在运行时重复启动会打开同一实例。
退出计时以浏览器与服务的事件流断开为准；电脑睡眠、浏览器冻结等情况可能延迟识别。

运行需要 Windows 上已有的 Node.js 22 或更高版本；本机已使用 Node.js 24 验证。
如果运行入口报错，可在此文件夹的 PowerShell 中执行：

    node src/service.cjs --open

停止：

    node src/service.cjs --stop

本机访问链接记录在 .runtime/instance.json；该文件包含随机访问凭据，请勿公开分享。
每次停止后重新启动可使用不同端口和凭据，应使用启动入口打开。

### 当前会话实验模式

默认按面板订阅汇总。实验模式开启后，监控先用仅由一个面板订阅的当前对话建立对应。切到共享会话时，只要仍是同一个 Webview 文档、原订阅仍能唯一确认该面板，且面板已订阅新会话，就会沿用同一行。面板重载、调试或 IPC 断线、订阅关系出现歧义时会重新核对，无法核对的行显示「当前会话未确认」。窗口跳转仍使用原有选择流程。

启动时已经在查看共享对话的窗口也可以确认。监控会排除已对应到其他 Webview 的面板，只有剩下一个候选且没有其他 Webview 同时指向它时，才显示该对话的状态。

1. 明确启用监控对指定端口的读取。若监控已运行，先用「停止监控.cmd」停止。设置会保存在本机 `.runtime/current-session.json`。

       node src/service.cjs --current-session-port=9222 --open

2. 以后双击「启动监控.cmd」。如果 VS Code 尚未运行，启动器会带本机调试参数打开 VS Code 和监控项目。如果 VS Code 已开启调试，直接使用当前实例。如果 VS Code 已按普通方式启动，保存工作并选择「文件 → 退出」，再双击启动器。

3. 要恢复默认模式，运行以下命令。监控已运行时，重启监控使更改生效。关闭以调试参数启动的 VS Code 实例后，调试端口也会关闭。

       node src/service.cjs --no-current-session --open

自动启动可通过 PATH 中的 `code` 或 `Code.exe`、Windows 应用注册表和常见安装位置查找 VS Code。使用自定义安装位置或专用用户数据目录时，也可以手动启动 VS Code，启动器会使用已经运行的实例。PowerShell 示例中的路径按实际位置修改。

    & 'C:\Program Files\Microsoft VS Code\Code.exe' --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222

调试接口只绑定本机，但其他能访问该端口的本机程序也可能用它检查或操作 VS Code 页面。监控只连接手动配置的端口，只查询活动会话标识和窗口关联所需的帧 ID。执行状态仍由只读 Codex IPC 提供。

## 页面

- 默认按已发现的会话面板汇总，可按状态筛选、搜索会话的项目名称/路径、优先显示空闲面板。展示按跟随会话的面板标识组织，执行状态仍由真正的会话拥有者提供；同一拥有者提供的会话可以出现在不同面板中。
- 面板订阅多个项目的会话时显示“多项目面板”，主列表列出会话项目名称，详情保留各会话的原始目录。会话目录不代表 VS Code 窗口的项目目录；IDE 目录核对不能证明面板对应哪个原生窗口。
- 同一会话被多个面板查看时，会在各面板下展示并注明“共享会话”，底部的独立会话总数只计算一次。未能确认面板对应关系的会话单独保留，标注“窗口归属待确认”。
- 手动阻塞：点击“标记阻塞”，可填写最多 500 字的原因；该窗口始终排在普通窗口之后，实际 Codex 状态和状态筛选保持不变。可编辑原因，点击“解除阻塞”恢复正常排序。
- 阻塞标记仅保存在本次监控服务的内存中，多标签页同步，刷新页面、切换会话或执行拥有者迁移时仍保留；面板客户端断开、重连核对确认面板已不存在或服务退出后清除，不写入文件。
- 空闲：当前轮结束，或有明确的等待用户输入标记。
- 执行中：Codex 正在处理当前轮，包括思考和调用工具。
- 待回答：当前交互中存在尚未收到已接受回复的结构化问题。按协议的有序历史索引和根轮次识别当前交互，新任务替换旧交互；自动续行和仅包含结构化问题回复的后续轮次延续原交互，历史旧问题不累加到当前计数。空闲时显示“等待回答”，仍在执行时显示“执行中 · 待回答”，统一使用琥珀色标签；回答或跳过并被接受后清除对应标记。
- 有待回答问题的窗口优先排列，手动阻塞仍始终置底；状态筛选和时长继续按真实执行状态计算。只检查当前交互的问题记录是否完整，更早历史未加载不会单独触发提示；当前交互记录不完整或未确认时会明确提示，断线后取消旧的待回答排序。
- 待处理：明确等待审批或确认。
- 面板中任一会话执行时显示执行中；没有执行中但有待处理时显示待处理；有状态未确认时不计为空闲，全部会话空闲才显示空闲。已知面板尚未取得快照或正在更换执行拥有者时，保留未知占位行。
- 未知：没有有效快照、断线、协议不兼容或正在重新同步。未知不会被计为空闲。
- 初次接入只能确认“至少已持续多久”；已观察到变化后，显示真实监测到的状态时长。
- 列表时长按分钟显示，未满一分钟显示“不到 1 分钟”；详情打开时按秒实时更新，超过一小时仍显示秒数。
- 详情显示项目路径、状态原因、窗口对应情况、最后确认时间及短标识。
- 每行“前往窗口”可激活现有 VS Code 窗口，并切到它所在的虚拟桌面；最小化窗口会恢复。
- 首次“前往窗口”时必须手动选择实际的 VS Code 窗口；会话项目可能与窗口项目不同，因此即使项目名称看似唯一匹配，也会列出所有候选窗口。选择框显示窗口标题、桌面及最小化状态，选择后本次监控运行期间会记住对应关系。
- 同一面板切换会话后仍可复用已选择的窗口；每次激活前都会核对原生窗口身份。窗口关闭重开、标题或窗口项目变化、面板重建或监控重启后可能需要重新选择，避免使用过期对应关系。选择仅关联窗口，不会在 Codex 中切换或控制对话。

## 覆盖与限制

当前已核对本机 openai.chatgpt 26.1106.51428（状态流版本 11）和 26.1111.21308（状态流版本 13）的相关快照、增量与运行状态结构，支持新旧窗口同时连接。升级期间，不同 VS Code 窗口可能仍在运行不同插件版本。
未适配的协议版本仍显示未知，并列出收到的版本和当前支持的版本；不会自动放行未经核对的版本。

采集通信断开时，旧条目会暂时保留并显示未知；重连成功后等待约 10 秒重新发现会话，未被重新发现的旧条目会自动移除。已重新发现但尚未取得状态的会话仍显示未知。

长会话的常规状态快照可能包含较大的历史数据。监控采用流式 JSON 解析，边接收边跳过无关正文，不为整条消息分配缓冲区或构建完整历史对象；仅临时读取有界的结构化回复文本以提取关联 ID，不写入文件。此方式减少监控端内存开销，不会减少 Codex 发出的数据量。

单条 IPC 消息接收上限仍为 256 MiB。超限时页面明确显示实际大小、上限、错误码、最近发生时间和累计异常次数；格式或解析资源异常也会明确提示。仅凭消息头无法定位来源窗口，因此该次采集连接的已确认状态会失效。错误在重试期间保留，重复解码失败逐步延长重试间隔（最多 30 秒）；取得有效快照且非空会话集合全部连续确认 30 秒后，异常提示自动恢复。诊断仅在内存中保留最后一条，不保存原始消息、异常正文或聊天内容。

列表代表已发现的 Codex 会话面板与待归属会话，不保证与物理 VS Code 窗口一一对应。同一面板可能保留多个会话订阅，不能据此判断当前选中的对话；隐藏/从未加载的面板也可能无法发现。不同面板即使目录相同仍保留独立行。通过客户端类型识别出的其他监控连接会被排除，但协议未提供完整客户端名册，未知订阅者不能一概证明是物理窗口。

订阅关系变化和面板断开会更新展示；采集断线时所有旧执行状态失效。重连后重新核对订阅，未重新发现的会话以及从未取得快照的面板占位都会清理。会话拥有者断开而面板仍在时会重新发现拥有者并恢复只读订阅。

等待输入/审批按明确的运行状态标记识别；异步问题另从常规快照和增量携带的 canonical history 中识别，仅保留问题和轮次关联 ID、数量、分页标记和同步状态。无关历史条目仅保留增量定位所需的索引占位，不解析其推理、工具输入或输出。不会持续请求完整历史；当前交互的普通请求起点、各根轮次起点和消息分页完整时，即使旧历史尚未加载也可确认问题状态。当前交互记录缺失、无法确认最新交互、超出解析上限或不支持的结构会标为未完全同步/未确认。协议测试覆盖不等于全部真实窗口场景均已实测。
工具不通过 CPU 占用、无输出时间或聊天内容猜测状态。

现有 IPC 未提供面板与原生窗口句柄的直接关联，“前往窗口”依赖本次运行中的手动选择，窗口标题仅用于后续验证绑定有效性。
Windows 若拒绝前台激活，页面会提示失败，可再点一次或按 Win+Tab 切换。
此功能使用 Windows 自带 PowerShell 与公开原生接口；仅点击时启动短时助手，不新增常驻进程。

## 本机与数据

仅监听 127.0.0.1，随机凭据保护页面和本地接口，浏览器通过事件流实时更新。
只保留最小状态元数据，不保存聊天正文、推理或工具输出。退出时不触及 Codex 工作进程。
没有系统服务、开机启动、桌面通知或远程访问。

## 开发

项目仅使用 Node.js 内置模块，运行无需 npm install。

现有自动检查：

    node --test

| 目录或文件 | 职责 |
| --- | --- |
| src/protocol.cjs、src/collector.cjs | IPC 消息帧、只读白名单、状态发现、订阅与重连 |
| src/stream-json.cjs | 有界流式 JSON 校验、元数据筛选及正文跳过 |
| src/state.cjs | 会话状态、修订校验、面板展示及独立会话计数 |
| src/current-session.cjs | 实验模式的本机活动会话标识读取 |
| src/input-state.cjs | 结构化问题与已接受回复的最小元数据投影 |
| src/web.cjs、src/service.cjs | 本机 HTTP/SSE、鉴权、单实例与服务生命周期 |
| src/windows.cjs、src/native/ | 窗口匹配及短时 PowerShell/C# 原生助手 |
| public/ | 面板、筛选、计时与窗口选择 |
| test/ | 现有协议、采集、网页、浏览器脚本及生命周期测试 |
| Start.ps1、Stop.ps1 | 启动和停止入口 |

开发约束见 [AGENTS.md](AGENTS.md)。自动协议测试不能替代真实 Windows 窗口、浏览器睡眠和长期运行场景的验证。
报告问题时，请提供 Windows、Node.js 和 Codex 插件版本，并对路径、项目名称、窗口标题及会话标识脱敏。
